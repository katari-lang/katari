## 記録

- `v0.1/records/` — v0.1 系の設計記録、マイルストーン、リリースの引き継ぎ、セキュリティ監査、記事の下書き
- `v0.2/records/` — v0.2 の設計記録：旧版の仕様、usage 評価とその採否、構文の案、Katari Protocol の設計記録

記録は、なぜそうなったかを知るために読む。記録同士の食い違いは解消しない。記録の中の「現行は〜」という記述は、書いた時点のものである。

## 書き方

- 現行の文書は、版を分けずにその場で書き換える。以前の版は git の履歴に残る。
- 記録のファイル名は `YYYY-MM-DD-<topic>.md` とし、書いた後は本文の内容を変えない。
- 記録の冒頭には状態を 1 行で書く：`状態：現行`、`状態：一部置換（→ <file> §n）`、`状態：置換（→ <file>）`、`状態：不採用`、`状態：未実装`。書いた後に変えてよいのはこの行だけである。
- 新しい記録が古い記録を置き換えたら、同じ commit で古い記録の状態の行を書き換える。
- 特定の版の仕様を対象にする評価は、`対象：spec/<file>.md @ <commit>` のようにコミットで版を指定する。

v0.1 の記録には、状態の行がまだ付いていないものがある。
