# doc-on-let: 値に説明が付く

owner 提案 (2026-07-24)。ツール説明の役割別上書き (PAIN 11) を、reflection プリミティブではなく
**let 束縛への説明アノテーション**として一般化する:

```katari
@"herald 版の説明: これはあなたが operator について知る唯一の窓です。"
let read_digest_for_herald = read_digest
```

説明は**値**に付く。`get_metadata` は (1) 値に紐づいた説明 → (2) 参照先 agent block の説明、の順で
解決する。将来「AI が変数の説明を読む」(実行状態の自己記述) にも同じ機構が使える。

## 意味論 (spec)

1. **付与**: `@"..."` が直前に付いた `let` は、束縛する値に description 属性をスタンプする。
   対象は任意の値 (agent 値に限らない) — ただし v1 の消費者は `get_metadata` のみ。
2. **伝播**: 説明は値と一緒に流れる (return / record 格納 / 引数渡しで保持)。後続の doc 付き let は
   **上書き** (最後のスタンプが勝つ)。doc なしの let は素通し (剥がさない)。
   — `private` taint と同じ「値属性」チャネルに乗せる。taint と違い monotonic ではなく last-write-wins。
3. **等値性**: description は `==` に影響しない (taint と同様、属性は同値性の外)。
4. **永続化**: 値属性として wire / 耐久状態を跨いで保持 (private の経路と同じ sealing 側路)。
5. **schema 導出**: `get_metadata` の description のみ差し替え。入出力 schema は参照先 block のまま。

## 決定 (owner 承認, 2026-07-24)

**metadata name も変数名で差し替える。** 「説明を付けて束縛した値は、その名前で世に出る」。
name はディスパッチキーだが、同名衝突は ai.ensure_unique_names が既に検出する。

**inner agent の doc 宣言も追加する** (別件として承認):

```katari
@"こんな感じで"
agent foo(...)
```

名前は宣言名 `foo`。調査の結果、lowering は StatementAgent の annotation を既に
`descriptionOf agentDeclaration.annotation` として受け取る配線になっており (Lowering.hs:641-654)、
inner agent の metadata name も最初から宣言名が載っている — 塞がっているのは
**statement 位置の `@"..."` を受理しないパーサだけ**。よって小修正。

二層の整理: **宣言名 (agent 宣言、doc は宣言に1つ) / インスタンス名 (doc 付き let、closure
ごとに differ)**。同じ宣言から mint した closure 群に別名を与えるのは let 側の仕事。
両機能は「statement 位置の annotation 受理」というパーサ変更を共有するので、1 実装単位とする。

## 実装スケッチ (blast radius)

- parser: `@"..."` を let 文の前で受理 (現状は宣言のみ)。AST: let 文に doc フィールド。
- lowering / IR: let の値経路に「description スタンプ」op (または let op の属性)。
- runtime: Value に description 属性 (private と並ぶ)。codec で保持。get_metadata の解決順変更。
- LSP: hover が変数説明を出せる (おまけ、後続)。
- テスト: 伝播 / 上書き / == 不変 / 再起動越え / get_metadata フォールバック。

「少し大きめの変更なので慎重に」(owner) — 本 spec のレビュー後に実装着手。
